# 遥控器 × Mac 端输入工具：语音收音能力矩阵

**这份文档是「界面显示什么、语音键怎么驱动」的唯一依据。** 代码里的推导在
`Sources/RemoteMic/VoiceInputCapabilityMatrix.swift`，回归断言在
`Tests/RemoteMicTests/VoiceInputCapabilityMatrixTests.swift`——**改任一处必须同时改三处**。

数据来源：2026-09-19 由用户提供并确认；标注「未测试」的项目在真机验收前不得当作已支持。

## 1. 遥控器能力

| 遥控器 | 长按收音 | 按一次收音 | 触摸面 |
| --- | --- | --- | --- |
| 小米遥控器（RC001 / RC003） | ✅ | ❌ | ❌ |
| Chromecase 语音遥控器 | ✅ | ✅ | ❌ |
| Apple Siri Remote（A2854 / A2540） | ✅ | 未测试 | ✅ |

- **按一次收音**：按一下开始收音，之后不必再按就能持续收音，结束收音需再按一次。
- **触摸面**：滑动/光标一类需要触摸表面的交互（Siri Remote 具备）。
- 「按一次收音」目前**只有 Chromecase 支持**——界面上的「语音键模式」（按一次说话 / 按住说话）
  也只在 Chromecase 的按键页出现。

## 2. Mac 端输入工具能力

| 输入工具 | 长按收音 | 按一次收音 |
| --- | --- | --- |
| Typeless | ❌ | ✅ |
| 豆包输入法（长按模式 / 免按模式） | ✅ | ✅ |
| 微信输入法 | ✅ | ✅ |
| Vokie | ✅ | ✅ |
| 腾讯 ChatterFly | ✅ | ✅ |

> 豆包输入法在设置里就是两个开关：**长按模式**＝按住说话、松手结束；**免按模式**＝按一次即可开始说话，
> **再按任意键结束**。这两种模式对「语音键」的期待完全相反，必须与遥控器/驱动的能力对上。

## 3. 搭配规则

1. **遥控器只能按住收音时**，工具必须支持长按；若工具只认点按（Typeless），
   **必须开启「语音键模拟 Fn 点按」**（它把「按住」模拟成一次点按）。应用在选择 Typeless 时会自动开启。
2. **遥控器支持按一次收音时**（Chromecase），驱动方式由它自己的语音模式决定，
   页面**不出现**「语音键模拟 Fn 点按」开关。
3. **触摸面类设置**（滑动箭头、光标反馈）只在具备触摸面的遥控器页面出现。
4. 其它同类能力（如电池位）同样按型号能力取舍，见各页面的适用性策略。

### 推荐搭配（按遥控器逐行给出）

| 遥控器 | 遥控器语音模式 | 输入工具应选 | 语音键驱动 | 「Fn 点按」开关 |
| --- | --- | --- | --- | --- |
| 小米 RC003 | 只能按住 | 豆包「长按模式」/ 微信输入法 / Vokie / ChatterFly | 按住—松开 | 不需要（若用免按模式则必须开启） |
| 小米 RC003 | 只能按住 | Typeless | 成对点按 | **必须开启** |
| Chromecase | 按一次说话 | 豆包「免按模式」等「按一次」触发的工具 | 成对点按 | 不显示 |
| Chromecase | 按住说话 | 豆包「长按模式」等「按住」触发的工具 | 按住—松开 | 不显示 |
| Apple Siri Remote | 只能按住 | 豆包「长按模式」/ 微信输入法 / Vokie / ChatterFly | 按住—松开 | 不显示（无触摸面无关的兼容需求） |

**一句话记法**：遥控器怎么收音，工具就配哪个模式；两边不同类时，才需要「Fn 点按」这个转接件，
而它只出现在「遥控器只会按住」的页面上。

## 4. 为什么「按一次收音」必须换驱动方式（实测依据）

宿主向第三方工具传递「开始/结束」只有一条通道：模拟 **Fn**。工具对 Fn 的期待分两类：

| 工具类型 | 对「按下」 | 对「松开」 |
| --- | --- | --- |
| 长按式（豆包「长按模式」、微信输入法…） | 开始收音 | **结束收音** |
| 点按式（豆包「免按模式」、Typeless…） | 切换（开↔关） | **无任何作用** |

真机实测（`Testing/VoiceKeyFnPanelProbe.swift`，注入 Fn 并采样豆包语音面板窗口）：

```
Fn 按下            → 面板出现
Fn 松开（等 2.5s） → 面板仍在        ← 点按式工具忽略松开
再按一次           → ~750ms 后消失
又按一次           → 再次出现
```

因此：**用「按住—松开」去驱动点按式工具，会让状态每两次按键才翻转一次**——真机表现就是
「按一下结束不生效、要再按一下（那一下其实已经是下一次开始）」。反之，用「成对点按」去驱动长按式工具，
会因为按下后立刻松开而在几十毫秒内结束收音。两种工具必须分别驱动。

细节与排查纪律见 `Testing/ChromecaseVoicePitfalls.md`。
