# Typeless 虚拟键盘快捷键测试

> 实验检查点：构建 228.2，尚未完成三模式文字上屏及稳定性验收。临时桥源码及构建依赖已归档于 [`scripts/typeless-vhid/`](../scripts/typeless-vhid/README.md)。以下按实验推进顺序保留历史结果；末尾为最新候选状态。

## 范围与准备

适用分支：`fix/typeless-custom-shortcut-events` 的本地候选构建。目标是让小米蓝牙遥控器 2 Pro 的确定键、菜单键、TV 键单击分别触发 Typeless 2.8.0 的语音输入、翻译、随便问。双击与长按不配置动作；本测试不改变独立语音键。

1. 保留 `/Applications/SayAll.app` 正式版，退出它，再启动独立标识的测试版 `dist/SayAllTypelessTest.app`。
2. 从 pqrs 官方发布包安装并启用 Karabiner VirtualHIDDevice，核对 `systemextensionsctl list` 为 `[activated enabled]`。官方 daemon 和受限桥必须运行；`/var/run/sayall-vhid-bridge.sock` 应仅允许当前用户连接。
3. 通过 Typeless 可见设置页核对三个快捷键分别为左 Control + 左 Option + V/T/Q。准备一个空白的 TextEdit 文稿并聚焦输入区；测试时不在用户正在编辑的文稿中操作。
4. 测试版应显示实体遥控器已连接，并拥有输入监控与辅助功能权限。确认三键单击映射为 `⌃⌥V`、`⌃⌥T`、`⌃⌥Q`，双击和长按均未设置。

## 分步验收

| 用例 | 操作 | 通过条件 | 失败判定 |
| --- | --- | --- | --- |
| 虚拟键盘直连 | 通过本地桥依次发送 V、T、Q，各模式用 V 结束 | Typeless 分别显示录音、翻译目标、询问任何问题状态，主快捷键结束录音 | 仅桥日志记录 `posted`，Typeless 无变化 |
| 实体确定键 | 在空白输入区按一次确定键；说“测试语音输入”；再按一次 | 首次出现语音输入状态，第二次结束，文字进入输入区 | 仅无线麦日志显示提交，Typeless 未出现，或有状态但文字未上屏 |
| 实体菜单键 | 按一次菜单键，说一句测试内容，再按确定键结束 | Typeless 出现“翻译为”及目标语言，随后退出 | 错误进入语音输入/随便问或无响应 |
| 实体 TV 键 | 按一次 TV 键，说一句测试内容，再按确定键结束 | Typeless 出现“询问任何问题”，随后退出 | 错误进入语音输入/翻译或无响应 |
| 其他映射回归 | 用遥控器下键等原有普通映射操作其目标 App | 按原有设置执行，不被 V/T/Q 桥截获 | 映射失效或发送多余组合键 |
| 桥断开与恢复 | 停止受限桥后执行三键，再重启桥复验 | 断开时记录明确失败且不自动补发 CGEvent；重连后下次请求恢复，无卡住的 Control/Option | App 卡住、修饰键保持按下，或恢复后仍无法触发 |

## 日志与证据边界

- 无线麦运行日志：`~/Library/Logs/RemoteMic/runtime.log`。核对 `HID BUTTON` 与 `SHORTCUT BRIDGE operation_id` 的顺序，区分 `queued`、`sending`、`completed result=acknowledged|unavailable|timed_out|expired`；`receiver=unknown` 表示桥回执不等于 Typeless 接收成功。
- 桥日志用于确认本地受限请求与虚拟键盘报告发送；不记录口述内容。Typeless 的最终状态须通过可见界面确认，文字上屏须通过空白输入区确认。
- 自动化测试可覆盖三键白名单和调用路由；不能替代实体遥控器、蓝牙、音频、第三方 App 前后台和真实文字上屏。未通过上述实机用例前只称候选版。
- 恢复方法：退出测试版，启动 `/Applications/SayAll.app`；正式版和用户的 Typeless 快捷键配置不随候选版覆盖。

## 非阻塞候选版回归

- 原始复现：HID 的按下和松开都已回调，但 session event tap 尚未处理按下。原实现会在松开时删除按下预约，导致原始 Return 漏出。两个回归用例在修改前共出现三项失败，修改后通过。
- 虚拟键盘请求在独立串行队列发送；一秒以上的过期排队请求丢弃并记录 `expired`，避免目标切换后迟到触发。socket 回执失败不自动换路径重发；请求一旦已发送，不能据超时判断目标一定未执行。
- 自动化：124 项 RemoteButtons 测试、3 项 VirtualHIDShortcutBridgeTests 通过。覆盖主线程在慢请求期间仍能处理事件、请求顺序、超时后下次恢复、过期请求丢弃，以及原始按下/松开各拦截一次。Apple Siri Remote 和外部硬件模拟依赖未在此公开构建启用，不宣称覆盖其真实硬件。
- 真机需要逐次记录：按键手势、原始事件拦截、桥回执、Typeless 可见模式、停止状态及测试文稿文字输出。三种模式各完成三次正常单击流程；开始和结束间隔至少两秒，不用连点或按住替代。
- 结束规则采用 Typeless 官方帮助：翻译/随便问的专用快捷键负责启动，主语音输入快捷键负责结束。同键结束另列探索项，不作为本轮基准。
- 麦克风输入单独核对。普通按钮只发送快捷键，不能据浮动栏出现就断言遥控器音频已经接入。

- 非阻塞候选构建 228.1 已启动，输入监控/辅助功能和 HID 连接均正常。直接通过受限桥发送 T/Q，截图分别确认翻译/随便问的录音波形，发送主快捷键 V 后浮动栏退出。AX 树在录音时也包含隐藏的 `Thinking` 文本，因此该词本身不能用于判断已停止。实体确定键的开始、结束、文字输出仍等待用户验收。

- 228.1 真机复验失败：用户反馈确定键完全没有启动 Typeless。对应六次有效操作（06:13 UTC）均记录 bridge acknowledged，确定键原生 Return 的按下/松开均有 suppressed；不能再把主线程阻塞或 session 层 Return 漏出视为全部根因。当前桥源码明确设置 left_control/left_option，但尚未比较系统实际接收的事件及 Typeless 对物理遥控器原生 HID 的响应。普通组合键模型只保存通用修饰标志，缺少用户可配置的左右侧别；这一能力缺口与本次固定左侧桥仍失败须分开处理。候选版仍未通过最终验收。


## 原生键中和对照（待实测）

- 先用只读 CGHID 探针对比实体键盘和遥控器：左右 Control/Option 的键码、flags、V 按下/松开及原始 Return 是否同时按下。已观察两条路径左侧 flags 相同，而遥控器 V 期间 Return 仍保持按下。
- 临时将此小米设备的原生 OK/Menu/TV usage 映射为 0，同时保留 App 原始报告读取与三键映射。验证映射读回、原始报告仍到达、注入期间 Return 不再按下，然后再验收 Typeless 可见模式与开始/结束。设置成功不是行为成功。
- 临时探针只观察相关修饰键、三组快捷键和原生按键，不采集任意输入内容；自动停止。中和实验 180 秒后仅恢复其拥有的三项映射，保留其他映射。
- 通过后才将中和逻辑接入 App 生命周期，并测试关闭自定义映射、改变动作、退出、重连与部分写入失败时的恢复；未通过前不得作为正式产品交付。


## 中和候选构建 228.2

- 前置实验结果：用户明确确认确定键能启动及结束；只读探针确认原始 Return 干扰消失、App 原始报告和 V/T/Q 仍正常发送。此结论不包含文字输出或三键稳定性。
- 候选实现仅在 `com.hd838a.RemoteMic.TypelessTest` 启用，仍依赖既有临时受限桥与官方驱动。只支持一台匹配小米设备；多台时恢复已拥有的中和映射并记录失败，不套用一个档案到其他设备。
- `RemoteShortcutNativeMapper` 拥有 OK/Menu/TV 中实际启用的来源，保留原映射；重复应用不能覆盖原值。改变快捷键、关闭自定义映射或正常退出后检查 `UserKeyMapping` 不再含对应新增 usage 0。其他映射的运行中修改必须保留。
- 自动检查覆盖三键中和、逐项释放、退出恢复、重复应用、读回不一致、恢复失败后重试，以及多设备拒绝和重新连接。实机补验菜单键进入翻译、TV 键进入随便问，确定键结束各模式；再分别验证真实输入和连续操作。
- 当前恢复只覆盖正常生命周期；强制终止或崩溃时系统映射可能持续至该键盘服务断开。这是本地候选的限制，不作为正式发布方案。

- 构建 228.2：140 项 Swift Testing 加 3 项 XCTest 通过，release 构建与独立测试包签名校验通过。实时验证关闭自定义按键后，仅保留原语音中和；重新开启后三个目标 usage 0 恢复；正常退出后映射为空，与启动前原值相符。重启后设备连接、两项权限和三键中和均恢复。安装位置仍为工作目录的独立测试包，正式 App 未替换。新构建上的三键模式及文字输出仍待用户验收。
